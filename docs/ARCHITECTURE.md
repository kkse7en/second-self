# 正式版架构与意图控制

2026-11-14。账号入口 /；独立样例 /sample；/planner 重定向。

## 应用分层与服务端边界

| 层 | 职责 | 关键入口 |
|---|---|---|
| app | Next路由、装配、API参数和限流 | page.tsx、api/ai/*/route.ts |
| ui | React交互、草稿、反馈、无障碍 | FinalPlanner、TaskEditor、IntakePanel、ReplanPanel |
| domain | Zod契约、冲突、周期、重排与写回护栏 | schemas、conflicts、time、reflow、planGuard |
| data | 按账号缓存、迁移、状态、快照与同步 | store、account-sync、account-cache |
| server | 认证、会话、SQLite持久化与版本控制 | accounts、account-http |
| ai | 服务端模型调用、JSON修复重试、规则降级 | tasks、prompts、guarded、demo |
| shared | 日期输入、样例和常量 | datetime、samples、constants |

业务UI通过store读写任务；账号外壳经account-sync调用账号API，AI交互经API请求模型。UI不直连数据库或模型SDK。domain不依赖React和IO；业务时钟显式传入。ESLint限制跨层导入。API密钥只在服务器环境读取。

## 业务闭环

录入：原文/图片 → API参数校验 → 规则或模型 → JSON与TaskDraft校验 → 文本覆盖与任务出处双向比对 / 图片不可独立核验提示 → 缺信息追问或核对卡片 → 关联已有安排 / 新增 / 忽略 → 用户确认 → TaskSchema → store → 账号缓存 → 防抖同步 → SQLite。文字比对基于字面线索，无法确认的条目进入人工核对，不等于语义真实性保证；默认90分钟的推断时长也必须核对。

重排：所选日期 + 全量任务/固定/周期/地点/截止 + 注入now/学期 → 模型或本地候选 → 结构校验 + guardPlan → 候选对照（原时间、调整后、冲突前后）→ 用户选择 → 指纹检查 + guardPlan再次校验 → 统一快照写回 → 单步撤销。

## 关键约束

- 时间区间半开；首尾相接不算重叠，但可能缓冲不足。周期只存一条，视图/检测时按周与学期展开并包含前一日跨午夜实例，按日完成不污染下周。
- 固定、周期、已完成任务不可自动移动；移动所选日任务，或为已确认工作量的截止任务安排准备时段，范围七天；整套候选联合检查时段、截止、日容量、新冲突和过去时间，日期拒绝无效日历值。
- 远期月历选择会移动周期检测窗口，now仍是实际/显式演示时钟，避免把查看未来当成已经到了未来。
- 方案结果指纹绑定输入。采纳前任务变化必须重新生成，避免旧AI结果覆盖新修改。
- 一个任务源、一个写入口。草稿追问与核对卡共享patch，不另存第二份正式任务。
- localStorage失败不能假报永久保存；网络也失败时明确显示未保存。导入先验格式、版本、日期及迁移，整体成功才替换。JSON只导出当前任务与设置，不携带历史撤销链；导入成功建立导入前快照。
- 空库持久化水合不访问undefined。账号初次读取显示轻量状态，会话检查完成后立即恢复数据。独立样例同步初始化，不向账号服务写入。

## 模型与安全

OpenAI兼容Chat Completions，JSON模式；AI输出拒绝未知字段，重排接收1–2套候选并按任务与实际时间去重，理由上限80字。AI_MAX_RETRIES默认1、范围0–3；修复轮保留原始文字/图片、上一轮输出及校验原因。用户数据通过JSON序列化传入，仍需结构与业务校验，不宣称能杜绝提示词注入。

文本/图片/重排入口共用认证、同源、异常处理及私有不缓存响应；非预期异常只记录接口标签，不记录原文、图片、密钥或异常详情。JSON解析前分别限制请求体64KB、3.21MB、6MB，超量返回413；单实例内存限流会清理过期项并限制桶数量，429附Retry-After。图片在浏览器压缩到长边1400px，PNG透明铺白，超限再降档；服务端核验PNG/JPEG/WebP的base64编码及文件签名，但不代替完整图像解码。

未配置密钥采用规则文本解析和本地重排。图片明确失败。真实模型输出永远是候选：格式合法仍可能理解错，人工核对不可省。

密码用scrypt随机盐摘要，随机会话仅存哈希；HttpOnly、SameSite=Lax Cookie，HTTPS时Secure。账号写入与AI接口校验同源及登录；鉴权只查身份与会话，不反复解析整份工作区。AI限流以账号为键，登录仅累计失败次数，成功清除对应失败计数。TRUSTED_CLIENT_IP_HEADER仅供会覆盖该头的可信代理配置，默认不信任外部转发头、共享local来源限流。公开部署仍需HTTPS、持久磁盘、可信代理及费用上限；内存限流不支持多实例。健康接口说明配置与数据库状态，不暴露精确运行版本，也不把已配置模型当作连通成功。

## 取舍

账号数据存服务端SQLite，localStorage只作按账号缓存；同一部署服务支持跨浏览器恢复。内置node:sqlite无需额外原生依赖，要求Node22.13+。纯函数保证固定输入下检测可重跑，不保证同Prompt的模型逐字一致。规则兜底可离线判断，浏览器访问应用/API仍需本地Next服务。没有Service Worker，不宣称PWA离线安装。

重复任务支持整组编辑、按次完成及确认后的单次调课。单次调课在 repeat.excludedDates 排除原日期，另存 occurrenceOf 关联的一次任务，不误动下周课程。重排采用保守启发式加本地裁决，不保证最优。截图使用隔离浏览器合成数据；浏览器回归与真实模型调用分开记录，不把规则样例作为模型准确率证明。

## 加载生命周期

异步操作仅显示静态状态文字，不添加展示等待。useRequestScope 为每次请求分配序号，关闭或卸载视图后忽略迟到结果；账号自动保存独立运行，不阻断操作。

## 账号与保存

GET session恢复会话；POST register/login/logout管理账号；GET/PUT workspace保存本人日程、快照、时钟、学期及头像昵称。服务端不接受任意userId读取；写入accountId必须与会话一致。450ms防抖串行写入，revision条件更新防止旧设备覆盖新修改。

每次修改尝试缓存；缓存失败只在当前页面保留内存副本。网络与缓存均失败时显示未保存，可保持页面重试或导出。刷新对比planner与同步元数据的时间标记，恢复较新的未确认编辑并要求选择版本；处理冲突期间又有编辑则拒绝覆盖，要求重新选择。未同步不能直接退出，退出不删除其他标签页可能在用的缓存。仍非实时协作，多标签页同时编辑没有独立草稿隔离。仅旧本机任务通过用户主动确认导入，不自动分配旧数据归属。

SQLite默认data/accounts.sqlite；ACCOUNT_DATA_DIR支持持久目录。数据库和密钥不公开分发；新安装从空账号库开始。未实现密码找回、邮箱认证、多实例或实时推送。早期无数据库决策保留于Git演进。

## 通知与准备时间

IntakePanel 的草稿始终先核对；IntakeChangeReview 给出关联候选，但不自动选中相似日程。用户可新增、更新或忽略；周期更新必须明确单次/整组，单次必须给出原发生日。confirmIntake 按输入指纹原子提交，一次快照支持整批撤销；遗漏、错误原日期、重复修改和陈旧输入拒绝写回。截图缺席不是删除指令。

estateMin 保存用户确认的准备工作量，与 deadline 交付时刻分开。仅从原文明确的“预计/需要 N 分钟”提取工作量；其余先问。scheduling.ts 在七天、07:00–23:00、15分钟网格内保守搜索；最多300条输入、30个待排任务。不拆分任务。“少改动”优先原时段附近，“优先截止”先排最近交付，再选较早空档。两套相同则去重，失败任务保留为约束，候选整套通过 guardPlan 才提供。

期限仅写日期时，检测与排程统一按当日23:59。准备排入并不等于完成任务；截止提醒仍可保留。风险总览先于月历显示未来两周待处理事项。

/sample 使用独立页面生命周期和无账号的内存状态，禁止缓存写入及账号同步；解析与排程仅调 domain 本地规则，不绕过正式AI接口鉴权。回到账号通过完整导航重建状态，从服务端恢复本人内容。

## 自动验证与公开样例

GitHub Actions 在 Windows / Linux 上执行 npm ci、verify 和生产构建；Linux 另跑浏览器核心流程和官方 registry 审计。浏览器在独立临时 SQLite 目录注册测试账号、验证自动保存与会话恢复，不使用真实密钥或用户数据。

build:demo 在隔离暂存目录移除账号及模型路由，仅静态导出 SampleApp。GitHub Pages 的 /second-self 子路径由资源前缀处理；样例用内存数据和本地规则，不接触账号服务，不承诺实时 AI 能力。完整服务继续采用 Node + SQLite 单实例持久盘。
